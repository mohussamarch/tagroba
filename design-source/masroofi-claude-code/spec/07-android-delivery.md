# 07 — اقتراح تنفيذ أندرويد والتسليم

## خيار تقني مقترح
إذا لم يوجد مشروع قائم: Kotlin + Jetpack Compose للواجهة، Room للتخزين المحلي، ViewModel مع تدفق حالة واضح، وإعدادات محلية منفصلة. هذا اقتراح تسليم مناسب لنطاق أندرويد، وليس قرارًا أصليًا ذكره المستخدم. Google توصي بـCompose لواجهات أندرويد الحديثة وبـRoom كطبقة فوق SQLite؛ راجع التوافق الحالي ولا تنسخ إصدارات عشوائية.

المراجع الرسمية (رُوجعت في 7 سبتمبر 2026):
- https://developer.android.com/topic/architecture/recommendations
- https://developer.android.com/training/data-storage/sqlite
- https://developer.android.com/training/data-storage/room/defining-data
- https://developer.android.com/training/data-storage/room/testing-db

افحص JDK وAndroid SDK وGradle وبيئة الجهاز أولًا. استخدم Gradle Wrapper وملف إصدارات مثبتًا مناسبًا. لا تفترض أن مجلد الحزمة يحتوي مشروع Gradle. اقترح حد Android أدنى مناسبًا للجهاز بعد الفحص، واستعمل target/compile SDK مستقرين متوافقين وقت البناء.

## هيكل مقترح
`android/` لمشروع أندرويد؛ فصل ui، domain (الحسابات)، data (Room والاستيراد)، وملفات fixtures للاختبار فقط. لا تبالغ في تعدد الوحدات قبل حاجة فعلية. اختبر الحسابات دون اعتماد على UI أو الشبكة. مصدر الحقيقة قاعدة البيانات، لا متغيرات الشاشة.

## الملفات والصلاحيات
اختيار كشف/CSV عبر منتقي ملفات النظام بدل صلاحية عامة للوصول لكل التخزين. قراءة الرسائل أو إشعارات البنك تحتاج مسار صلاحيات فعليًا مناسبًا لإصدار أندرويد؛ تحقق منه قبل الوعد بأنه تلقائي. إذا رفض المستخدم الصلاحية، يبقى الإدخال والاستيراد اليدوي عاملين. لا تتطلب بيانات اعتماد بنك.

تصدير نسخة احتياطية واستعادتها محليًا، مع خيار تشفير مصمم ومختبر؛ لا تضع مفتاحًا ثابتًا بالكود. القفل ببصمة/قفل جهاز يطبق فقط بعد اختبار العودة من الخلفية، مع عدم طباعة المبالغ الحساسة في السجلات. لا تدّعِ أن قفل الواجهة وحده يشفر قاعدة البيانات.

## المطلوب تسليمه
1. الكود الكامل القابل للبناء، بإصدارات وأوامر Windows موثقة.
2. APK تجريبي بعد نجاح البناء، ثم نسخة شخصية موقعة عند تجهيز مفتاح المستخدم بأمان.
3. قيمة SHA256 لملف APK وتعريف النسخة وتاريخها، ومصدر البناء.
4. خطوات عربية بسيطة للتثبيت على S24 Ultra ومنح الصلاحيات الضرورية فقط.
5. تعليمات النسخ الاحتياطي والاستعادة وتحديث التطبيق دون فقد البيانات.
6. ملخص اختبارات واقعي، وميزات غير مكتملة/غير مدعومة إن وجدت.

مفتاح التوقيع وكلمات مروره لا يدخلان Git أو ZIP التسليم العام. النسخ التالية تحتاج نفس التوقيع للاحتفاظ بمسار التحديث. أول APK تجريبي يجب تسميته كذلك؛ لا يُوصف بالإصدار النهائي قبل استيفاء النطاق واختبارات القبول.

تصميم HTML تفاعلي v4، وثائق، قواعد/أسماء تجار، مراجعة منطق المعاينة باختبارات محلية، ونشر الملف نفسه داخل إطار معزول على Sites. لم يُنشأ مشروع أندرويد أو APK، ولم يُختبر PDF حقيقي أو هاتف في هذه المرحلة. نشر الويب لا يوفّر قاعدة بيانات أندرويد أو خدمة مزامنة.
