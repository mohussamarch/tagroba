# 05 — الاستيراد ومراجع المعالجة

## CSV
ادعم مخطط المعاينة: `date,name,amount,type,source,reference`، حيث amount موجب، type هو expense/income/transfer، والتاريخ ISO. ادعم BOM وUTF-8 والفواصل داخل الاقتباس والأسطر CRLF والأرقام العربية. قدم تعيين أعمدة للملفات المختلفة؛ لا تخمن الأعمدة المالية بصمت.

ادعم أيضًا مخطط السكربت القديم: `التاريخ,مدين,دائن,الرصيد,التاجر,التصنيف,نوع العملية,التفاصيل`. التاريخ بصيغة YYYY/MM/DD، والمدين/الدائن يحددان اتجاه السيولة، لا النوع الاقتصادي. المخططان غير متطابقين؛ مطلوب adapter صريح. لا تستورد ناتج السكربت كأنه CSV المعاينة دون تحويل.

الحقول غير الصحيحة تدخل قائمة أخطاء برقم الصف، ولا تُستورد نصف دفعة دون توضيح. احتفظ بالنص الأصلي للمراجعة. لا تقبل مبلغًا غير محدود أو NaN، ولا تاريخًا استحالته مكتومة. ضع حدودًا للملف وعدد الصفوف والوقت مع رسالة واضحة.

## التكرار
1. بصمة ملف مطابق سبق استيراده: اعرض الدفعة السابقة ونتيجتها بدل إضافته من جديد.
2. مرجع بنكي + هوية حساب/مصدر مطابقان وتفاصيل متطابقة: مكرر مؤكد.
3. مرجع مطابق وتفاصيل مختلفة: تعارض، لا استبدال صامت.
4. تاجر + مبلغ + تاريخ + اتجاه + مصدر متشابه دون مرجع موثوق: مرشح مراجعة، لا حذف تلقائي؛ عمليتا مطعم بالمبلغ نفسه قد تكونان حقيقتين.
5. رسالة وكشف لنفس العملية: SourceRecords متعددة لعملية واحدة بعد المطابقة. طرفا تحويل داخلي يُربطان ولا يُحسبان دخلًا أو مصروفًا.

حالة المراجعة تعرض جديد/مكرر/متشابه/تعارض/غير صالح، ومجموع أثر المحدد على المحفظة والمصروف. إعادة الضغط أو إعادة فتح التطبيق لا تعيد الالتزام بالدفعة. التراجع يحترم العمليات المرتبطة بتسويات أو مصادر أخرى.

## التصنيف
الأولوية: تأكيد المستخدم على العملية → تعيين التاجر المؤكد → القواعد المرتبة → اقتراح للمراجعة. لا تستبدل المؤكد عند إعادة الاستيراد. ملفات القواعد مرجع أولي قابل للتحرير، وليست سياسة لا تتغير. طبعنة العربية واللاتينية للبحث دون إتلاف النص الأصلي.

## legacy/parse_alrajhi.py
النسخة الأصلية مرفقة دون تعديل. تعتمد على pdfplumber وإحداثيات أعمدة صفحة A4، وتقرأ rules_categories.csv بجوار PDF أو من مجلد التشغيل، وقد تقرأ ملف تصنيف التجار بجوار المصدر. افحص الكود قبل الاستخدام. مخرجاتها تتضمن مدين ودائن ورصيدًا وتفاصيل.

هذه ليست مكتبة أندرويد. يمكن تطويرها كأداة تحويل محلية مساعدة على Windows في مرحلة مبكرة، مع بقاء استخراج PDF على الجهاز ضمن العمل المطلوب؛ لا تضف خدمة سحابية لمجرد تشغيل Python.

حدود معروفة: التقاط نوع العملية قد ينزلق إلى ترويسة مجاورة؛ الإحداثيات تعتمد على القالب؛ عكس النص العربي لا يناسب كل PDF؛ المبالغ في السكربت تستخدم float. لا تعتمد ادعاء الدقة 100% من الملاحظات القديمة. قبل الاعتماد اختبر صفحات متعددة وتغير القالب وتتابع الرصيد والإجماليات. PDF ممسوح ضوئيًا يحتاج مسار OCR واضحًا أو رسالة عدم دعم، لا نجاحًا وهميًا.

## legacy/detect_subs.py
مرجع قديم يحتاج معالجة قبل الإنتاج: تاريخ NOW ثابت 2026/09؛ قراءة وتنفيذ على مستوى الوحدة؛ مسارات افتراضية؛ أرقام float؛ قاعدة رسوم نسبية استدلالية وليست إثباتًا. منع رسوم من تضليل اكتشاف الاشتراك لا يعني حذفها من المصروف المالي.

الدورية امتداد عبر عدة شهور + تواتر محدود + مبلغ/موعد متقارب + طبيعة خدمة مناسبة. عدد 126 زيارة لمطعم لا يثبت اشتراكًا. التصنيفات المستبعدة لا تجعل المدفوعات مدخرات تلقائيًا. مرشح الاشتراك يحتاج تأكيدًا، والرسوم مرتبطة دون مضاعفة.
